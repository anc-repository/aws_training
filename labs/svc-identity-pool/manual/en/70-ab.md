A runtime A/B in the same deployment: when an admin opens a session with `X-Compare-Bypass: identity-pool`, that one session gets a prefix token from the none driver, while every other request uses STS as usual.
The bypass header only works on `POST /api/uploads/session`, and only for admins.

Sign in to the app as an admin, open `/lab`, choose identity-pool in the A/B runner, send two session requests, and look at the identity-pool segment of each `X-CloudAlbum-Path` response header.

:::expected
With the bypass header: `identity-pool=cognito:bypass`, and the response body is a `mode: token` prefix token; without it: `identity-pool=cognito:session`, and the response body is `mode: sts`
(that only opened the session; `identity-pool=cognito:sts` only appears once `GET /api/uploads/credentials` successfully exchanges for credentials).
When Cognito or the staging bucket is unavailable, regular sessions also fall back to prefix tokens, with the path segment `cognito:error-fallback` (the badge in the upload dialog turns yellow).
:::
