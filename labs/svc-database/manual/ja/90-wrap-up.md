## このラボでできたこと

- SQLite をマルチ AZ の RDS for PostgreSQL に置き換え、同じリポジトリコードのまま、マネージドなバックアップ、ポイントインタイムリカバリ、自動フェイルオーバーを手に入れました。
- 自分でフェイルオーバーを起こし、プライマリの AZ が変わり、アプリが一時的な書き込み失敗の後に自動で再接続する様子を確認しました。
- データベースにはラボ用インスタンスからしか接続できないこと（セキュリティグループの連鎖＋パブリックアクセス不可＋ TLS の強制）を確認しました。

## 試験ポイントの振り返り

- マルチ AZ のインスタンスデプロイ vs マルチ AZ の DB クラスターデプロイ vs リードレプリカ。
- 自動バックアップ（最長 35 日）、ポイントインタイムリカバリ（新しいインスタンスとして復元）、手動スナップショット、スナップショットのクロスリージョンコピー。
- 暗号化は作成時にしか有効にできません。暗号化されていないインスタンスは「スナップショット → 暗号化してコピー → 復元」で暗号化に切り替えます。
- RDS によるマスターパスワードの管理とローテーション、IAM データベース認証、RDS Proxy の位置付け。停止したインスタンスは最大停止期間を過ぎると自動で起動されます。
