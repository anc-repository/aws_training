## 你做到了什么

- 让事务邮件经 SES 真正发出：验证码到达了你的收件箱；沙盒拒绝未验证地址时，应用如实记为失败。
- 搭好了退信与投诉的回流通道：配置集事件目标 → SNS → SQS 反馈队列 → worker，实验机没有开放任何入站端口。
- 把“有新评论”的站外扇出交给 SNS：发布一次，按 `userId` 过滤策略投递到对应用户的邮件订阅，并复制到收件队列；worker 停机时消息在队列里等待。

## 整体对比

| 指标 | 开始时 | 完成后 |
|---|---|---|
| 一次事件的投递方式 | EC2 逐个调用 EmailPort | 发布一次，SNS 投递 |
| 发布方耗时与人数的关系 | 线性增长 | 基本不变 |
| 用户能否收到邮件 | 不能（只有 outbox） | 能（沙盒期只发给已验证地址与邮箱模拟器） |
| 谁决定“谁该收” | 应用代码 | 订阅过滤策略（SNS 侧） |
| 渠道扩展 | 改应用代码 | 新增订阅（SQS、Lambda、HTTPS、短信等） |
| EC2 需要的入站端口 | 无 | 无（SNS → SQS、SES → SNS → SQS 都由 worker 拉取） |
| 退信与投诉 | 不存在 | 事件回流，自动停止给无效地址发非必要邮件 |

## 考点回顾

- SNS 主题、订阅协议、订阅过滤策略（消息属性 / 消息体）、邮件订阅确认、原始消息传递、订阅级 DLQ；SNS FIFO + SQS FIFO 用于有序扇出。
- SNS + SQS 扇出与 SQS 竞争消费的区别；队列在消费者停机时缓冲消息；队列策略中的 `aws:SourceArn`。
- SES 身份验证（邮箱 / 域名）、DKIM、SPF、DMARC；沙盒与生产访问（按区域）；发送配额与速率。
- SES 配置集与事件目标；用 SNS + SQS 把 AWS 服务的异步事件安全地送回没有入站端口的应用。
- SNS、SES、EventBridge 的适用场景；EC2 默认限制出站 25 端口。
