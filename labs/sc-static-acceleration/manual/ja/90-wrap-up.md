## このラボでできたこと

- プライベートな S3 バケットの前に CloudFront を置きました。サムネイルの URL は固定の `https://<ディストリビューションのドメイン名>/media/variants/…` になり、エッジでもブラウザーでもキャッシュできます。
- OAC + `AWS:SourceArn` で、バケットをプライベートかつ BPA をすべて有効のままにし、このディストリビューションにだけ `variants/*` を開放しました。
- 無効化とバージョン付きファイル名を比較しました。

## 全体の比較

- **メディアの URL**：毎回異なる署名付き URL → ディストリビューションのドメイン名の固定のアドレス。
- **オリジンの負荷**：すべてのリクエストが S3 か EC2 に届く → 残るのはオリジンリクエストだけ。
- **バケットの公開範囲**：プライベートで署名付き URL に依存 → プライベートで、このディストリビューションだけが OAC 経由で `variants/*` を読める。
- **時間課金のリソース**：変わらない（追加したサービスはすべて使用量課金）。

## 試験ポイントの振り返り

- エッジロケーションとリージョン別エッジキャッシュ。キャッシュポリシー、オリジンリクエストポリシー、レスポンスヘッダーポリシー。TTL と `Cache-Control`。
- OAC と OAI。CloudFront だけに S3 へのアクセスを許可するバケットポリシー。SSE-KMS のオブジェクトにはキーポリシーで CloudFront への許可が必要。
- CloudFront で使う ACM 証明書は us-east-1 になければならない。Route 53 の Alias はルートドメインにも使え、AWS リソースを指すクエリは無料。ルートドメインには CNAME を置けない。
- CloudFront、S3 Transfer Acceleration、Global Accelerator の比較。AWS のオリジンから CloudFront への転送は無料。
