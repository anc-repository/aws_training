## Background

L0's port 443 uses a self-signed certificate generated by User Data (`CN=cloudalbum-l0`): traffic is encrypted, but the browser says "Not secure", and cross-origin fetches and Cognito callbacks fail.
AWS Certificate Manager has two ways to provide certificates: **integrated certificates** attach to CloudFront, ALB and API Gateway, with the private key managed by ACM, not exportable, and renewed automatically;
since 2026-07, ACM's **ACME endpoint** can issue 45-day public certificates for self-managed servers, with the private key staying on the instance and certbot handling renewal.

:::warning
**Manual prerequisite: your own domain**, where you can add a CNAME (ACME domain validation or ACM DNS validation) and an A record (pointing at the lab instance's EIP) in its DNS. ACM cannot issue certificates for IPs,
`amazonaws.com` or `cloudfront.net` names. If this account has a Route 53 hosted zone for the domain, `--zone-id` creates the validation records automatically.
Without a domain this card cannot be completed: `scripts/module enable tls` prints a message and exits with code 2 without deploying anything.
:::

:::saa{domain=secure}
**The exam answer**: ACM public certificates cannot be installed on EC2 and only attach to integrated services; the certificate CloudFront uses must be in us-east-1.
**The 2026 capability**: the ACME endpoint + pre-approved DNS domain validation + EAB installs certificates on self-managed servers; conversely, such certificates cannot be attached to CloudFront or ALB. Answer exam questions with the exam answer.
:::

## Comparison experiments

### Certificates at each entry point (tls/inspect, required)

- **Without ACM**: the certificate on direct `https://<EIP>/` is self-signed by `CN=cloudalbum-l0` and the chain is not trusted; the path header is `tls=selfsigned@nginx`.
- **With ACM**: in the ACME branch the direct certificate is issued by Amazon, its SAN contains your domain, and it lasts about 45 days; in the fallback branch the CloudFront alternate domain name shows the us-east-1 integrated certificate.
- **Where you see it**: the issuer, SAN, days remaining and `trustedEntries` of each entry point in the comparison report; the server-side evidence is the tls sensor's handshake with `127.0.0.1:443` on the lab instance
  and `capabilities.https`.
- **If the results are not what you expect**: look at tls's status detail first — “签发者不是 Amazon” (issuer is not Amazon) means the certificate symlinks were not switched or Nginx was not reloaded.

### Renewal drill (tls/renew-drill, ACME branch)

`certbot renew --dry-run` and `--force-renewal`: the new certificate goes into Nginx, and the certificate ARN in ACM stays the same (same ACME account, same domain and key algorithm).

## Platform mode notes

This card turns off the platform's option B preview (the Let's Encrypt IP certificate), so the preview opens `http://<EIP>` in a new tab. Before you start, the platform uses an account preflight to decide whether the ACME endpoint is available
and picks the starting variant (now: `{{ session.variant }}`): `default` takes the ACME branch; `acme-off` adds a CloudFront distribution to the start state and takes the fallback branch.
