## このラボでできたこと

- 自己署名証明書から信頼された ACM 証明書に移りました。ACME の分岐では Nginx に導入し、フォールバックの分岐では CloudFront に付けました（証明書は us-east-1）。
- サーバー側の証拠（ラボ用インスタンス自身でのハンドシェイク、プラットフォームがドメインでアクセスしたときの証明書 SAN の照合、ACM のコントロールプレーン上の証明書）で、証明書が本当に有効になったことを確認しました。
- 「試験の結論」と「2026 年の新機能」を区別しました。

## 試験ポイントの振り返り

- ACM のパブリック証明書は統合サービスで使う場合は無料で自動更新され、秘密鍵はエクスポートできない。DNS 検証と E メール検証。更新には検証レコードを残しておく必要がある。
- 証明書のリージョン：CloudFront と Cognito のマネージドログインページのカスタムドメインは us-east-1、ALB とリージョン API Gateway はリソースのあるリージョン。
- インポートした証明書は手動で更新する。ACM Private CA は内部向けの証明書に使う。
- SNI と「1 つのリスナーに複数の証明書」。ALB からターゲットへの通信も再暗号化できるが、ALB はターゲットの証明書を検証しない。
- HSTS。エッジで TLS を終端すると、遠方のユーザーのハンドシェイク遅延を減らせる。
