ACM コンソールの証明書一覧で「キーペアのオリジン：ACME」で絞り込み（絞り込まないと ACME 証明書はデフォルトでは表示されません）、この証明書のオリジンと更新方法を確認します。

| | 試験の結論（SAA の問題集でよくある答え） | 2026 年の新機能（このカードの ACME の分岐） |
|---|---|---|
| ACM 証明書を EC2 に導入できるか | **できない**：秘密鍵は ACM が管理しエクスポートできず、CloudFront、ALB、API Gateway にしか付けられない | ACME エンドポイントが 45 日の証明書を発行し、秘密鍵はインスタンス上にあり、Nginx に導入する |
| 更新 | ACM が自動で更新を管理（DNS 検証のレコードを残しておく必要がある） | クライアント（certbot のタイマー）が更新し、ACM は関与しない |
| CloudFront / ALB に付けられるか | できる（CloudFront には us-east-1 の証明書を使う） | **できない** |

:::expected
ACME 証明書の「キーペアのオリジン」は ACME で、「マネージド更新」はありません。CloudFront ディストリビューションのカスタム証明書として選ぶことはできません。
:::

:::saa{domain=secure}
解答は左の列を基準にします。「EC2 で ACM 証明書を使って TLS を終端する」の標準的な答えは、前に ALB / CloudFront を置くか、サードパーティーの証明書をインポートすることです。
:::

::checks
