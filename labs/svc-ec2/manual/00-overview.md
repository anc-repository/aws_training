## 背景

CloudAlbum 的 L0 只有一台 EC2：Nginx、api、worker、SQLite 和上传文件都在这台机器上，应用不加载 AWS SDK、不调用任何 AWS API。
它与“传统单机部署”最大的区别是：数据、机密与本地配置都在**独立数据卷**上（`/etc/cloudalbum → /var/lib/cloudalbum/etc`），
根卷可以随时重建。但它仍然是单点——停掉实例就是全站中断。

:::why
这张卡片没有“启用模块”的步骤：ec2 是基础模块。你要做的是看清 L0 的性质——哪些东西会随实例消失、哪些不会、
哪些地方是安全底线——之后每张卡片都在它的基础上替换一个部件。
:::

## 对比实验预告

ec2 没有“有 / 无”的对比实验：本卡验证的是 L0 的性质，把传统单机部署的做法与 L0 的做法放在一起对照。

- **公网地址**：没有 EIP 时，停止再启动后公网 IPv4 会变；L0 用 EIP，地址不变（第 5 步亲测）。
- **数据与机密的位置**：放在根卷上，重建实例就会丢数据、重新生成密钥；L0 放在独立数据卷上（第 3 步巡检）。
- **实例元数据**：IMDSv1 下任何 GET 请求都能读到元数据；L0 强制 IMDSv2，不带令牌返回 401（第 4 步）。
- **单点**：停止实例 = 全站不可用——L0 也是单点，这正是负载均衡、弹性伸缩与备份卡片要解决的问题。

## 平台模式说明

实验机上挂着平台的管理角色（只用于 SSM 管理通道），应用自己没有 AWS 身份。第 5 步停机期间，实验机终端与本地检查会显示“预期中断”。
