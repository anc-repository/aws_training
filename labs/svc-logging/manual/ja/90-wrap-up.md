## このラボでできたこと

- アプリに同じログを CloudWatch Logs へまとめて送らせ、ローカルファイルへの書き込みも続けました。ロールバックしてもデータの欠落はなく、インスタンスがなくなってもログは残ります。
- 取り込みの遅延を測りました。ローカルでは即座に、CloudWatch では秒単位で見えます。
- Logs Insights で 5xx を集計し、「スキャンしたバイト数」という課金の基準を確認しました。メトリクスフィルターでログをメトリクスに変えました。

## 試験ポイントの振り返り

- ロググループ、ログストリーム、保持期間（デフォルトは失効しない）、KMS 暗号化。ログクラスの Standard と Infrequent Access。
- EC2 上のログには CloudWatch エージェントか SDK が必要。Lambda のログは自動で入る。統合 CloudWatch エージェントはログとメトリクスを同時に収集する。
- メトリクスフィルター → メトリクス → アラーム、過去にはさかのぼらない。Logs Insights はスキャン量で課金。サブスクリプションフィルター（Kinesis / Firehose / Lambda）はほぼリアルタイム、S3 へのエクスポートはバッチ。
- CloudWatch Logs（稼働ログ）と CloudTrail（API の監査）の違い。
