## このラボでできたこと

- アプリに初めて AWS の ID を持たせました。インスタンスロールの一時的な認証情報で、ディスクに書かれず、自動でローテーションされます。
- IMDSv2 が GET しか送れない SSRF を防ぐことを確認し、CloudTrail で `AssumedRole` と `ASIA` を見分けられるようになりました。

## 試験ポイントの振り返り

- IAM ユーザー、グループ、ロール、ポリシー。AWS 管理ポリシー、カスタマー管理ポリシー、インラインポリシー。インスタンスプロファイルと `iam:PassRole`。
- STS の一時的な認証情報と自動ローテーション。`aws:TokenIssueTime` とセッションの取り消し（インスタンスは新しいセッションに切り替わるまで復旧しません）。
- IMDSv2 と SSRF、ホップ数の制限。SDK の既定の認証情報チェーンの優先順位。
- ポリシーの評価ロジック：明示的な Deny が優先、既定は拒否、`GetCallerIdentity` は例外。アクセス許可の境界、SCP、アイデンティティベースのポリシーの関係。
