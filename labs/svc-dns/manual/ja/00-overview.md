## 背景

L0 のアルバムには `http://<EIP>` でアクセスしています。ブラウザーのアドレスバーにも、登録確認メールにも、共有リンクにも、この IP が書かれています。アドレスが変わると（インスタンスの交換、ネットワークの移行、
前段への ALB や CloudFront の追加）、すでに送ったリンクはすべて使えなくなります。Amazon Route 53 はアルバムに固定の名前を付けます。名前の背後の宛先はいつでも交換でき、
ユーザーの手元のリンクは TTL が過ぎれば自動で新しい宛先を指します。

:::warning
**手作業の前提条件：自分のドメイン。** このカードには、DNS を管理できるドメインが必要です。次のどちらかです。① このアカウントにそのドメイン（またはサブドメイン）の Route 53 パブリックホストゾーンがすでにある（推奨。
委任を待つ必要がありません）。② レジストラーまたは親ドメインで、サブドメイン（例：`lab.example.com`）の NS 委任を追加できる（反映までの時間はレジストラーとトップレベルドメイン次第で、カードの制限時間を超えることがあります）。
ドメインがないとこのカードは完了できません。`scripts/module enable dns` はメッセージを表示して終了コード 2 で終わり、何もデプロイしません。
:::

:::why
ドメインの登録と DNS ホスティングは別物です。レジストラーは「このドメインは誰のもので、どのネームサーバーが回答するか」を決め、ホストゾーンは「ネームサーバーがどう回答するか」を決めます。
新しいホストゾーンには専用のネームサーバーが 4 つあり、レジストラー（または親ドメイン）が NS をそれらに向けて初めて、世界中のリゾルバーが Route 53 に問い合わせるようになります。
:::

## 比較実験の予告

### IP 変更の訓練（dns/ip-change-drill、必須）

- **Route 53 なし**：訓練スクリプトが一時的な Elastic IP を割り当ててラボ用インスタンスに関連付け、「インスタンスが交換されて IP が変わった」状況を再現します。古い IP のリンクを 5 秒ごとに確認すると、すべて失敗します。
- **Route 53 あり**：同じ訓練で、スクリプトはレコードを新しい IP に UPSERT します。パブリックリゾルバーは TTL（60 秒）程度の時間で新しいアドレスを返し、ドメイン名のリンクは自動で復旧します。
- **どこで確認できるか**：比較レポートの `oldLinkFailures`、`domainFailures`、`resolverSwitchSec`、`domainRecoverySec` です。サーバー側の証拠は、ラボ用インスタンス上の
  dns 検知処理の解決結果とリクエストの `Host` の分布、そしてドメイン名経由で `/api/lab/echo` にリクエストしたときにサーバーが受け取った `Host` です。
- **期待どおりにならないとき**：2 回の実行の両方に `--fault-via local` を付けたか確認してください（訓練スクリプトはワークベンチで AWS CLI を呼び出します）。after の前に委任が反映されている必要があります。

### フェイルオーバー（dns/failover-drill、任意）

プライマリレコードにヘルスチェックを関連付けます。Nginx を止めると、クライアントは「チェック間隔 × 失敗のしきい値 + TTL + キャッシュ」の後にセカンダリのレコード（S3 の静的メンテナンスページ）を受け取ります。

## プラットフォームモードについて

このカードでは `scripts/module enable dns` で、ホストゾーン（またはあなたの既存のホストゾーン）とレコードを一括作成します。プラットフォームはこのセッションの dns スタックで所有を確認します。
レジストラーで追加した NS 委任や、コンソールで手動作成したレコードはプラットフォームの回収対象外です。終了前に自分で片付けてください。
