step: domain

変数パネルで、入力したドメイン `{{ learner.inputs.domain }}` を確認します。このアカウントにそのドメイン（またはその親ドメイン）のパブリックホストゾーンがすでにある場合は、ホストゾーン ID も入力してください。
次のステップで委任を待つ必要がなくなります。

まず、この名前がいまどこに解決されるかを見ます（レコードがなければ空が返ります）。

```bash {runsOn=workstation}
dig +short {{ learner.inputs.domain }} @8.8.8.8
dig +short NS {{ learner.inputs.domain }} @8.8.8.8
```

:::tip
CloudShell やワークベンチに `dig` がない場合は、先に `sudo dnf install -y bind-utils` を実行します。`@8.8.8.8` を付けるとローカルのキャッシュを通らず、パブリックリゾルバーの回答を直接見られます。
:::

:::expected
dns をまだ有効にしていなければ、1 つ目のコマンドは通常空を返します（またはどこか別の場所で設定した古いレコードを返します）。2 つ目のコマンドはこの名前の現在のネームサーバーを返します。
Route 53 のホストゾーンがすでにある場合は、4 つの `awsdns` ネームサーバーです。
:::

:::why
**なぜサブドメインを推奨するのでしょうか？** `lab.example.com` のようなサブドメインだけをホストすれば、メインドメインのほかのレコード（Web サイト、メール）に影響しません。親ドメインには NS レコードを 4 つ追加するだけです。
`example.com` 全体をホストするには、レジストラーで NS をすべて変更する必要があり、影響範囲がずっと大きくなります。
:::

::checks
