## 背景

L0 的相册用 `http://<EIP>` 访问：浏览器地址栏、注册验证邮件、分享链接里写的都是这个 IP。只要地址变化——换实例、迁移网络、
前面加上 ALB 或 CloudFront——已经发出去的链接就全部失效。Amazon Route 53 给相册一个固定的名字：名字背后的目标可以随时更换，
用户手里的链接在 TTL 过后自动指向新目标。

:::warning
**人工前置：自有域名。** 本卡需要一个你能管理 DNS 的域名，二选一：① 本账号已有该域名（或其子域）的 Route 53 公有托管区域——推荐，
不需要等待委派；② 能在注册商或父域为一个子域（例如 `lab.example.com`）添加 NS 委派——生效时间由注册商与顶级域决定，可能超出卡片时长。
没有域名时本卡无法完成：`scripts/module enable dns` 会打印提示并以退出码 2 结束，不部署任何东西。
:::

:::why
域名注册与 DNS 托管是两件事：注册商决定“这个域名归谁、由哪几台名称服务器回答”，托管区域决定“名称服务器怎么回答”。
新建的托管区域有自己的 4 个名称服务器，注册商（或父域）把 NS 指向它们之后，全世界的解析器才会来问 Route 53。
:::

## 对比实验预告

### 换 IP 演练（dns/ip-change-drill，必做）

- **没有 Route 53**：演练脚本分配一个临时弹性 IP 并关联到实验机，模拟“实例被替换、IP 变了”；旧 IP 链接每 5 秒探测一次，全部失败。
- **有了 Route 53**：同样的演练里，脚本把记录 UPSERT 到新 IP；公共解析器在 TTL（60 秒）量级的时间内返回新地址，域名链接自动恢复。
- **你会在哪里看到**：对比报告中的 `oldLinkFailures`、`domainFailures`、`resolverSwitchSec`、`domainRecoverySec`；服务端证据是实验机上
  dns 感知器的解析结果与请求 `Host` 分布，以及经域名请求 `/api/lab/echo` 时服务端看到的 `Host`。
- **如果结果不符合预期**：确认两次运行都带了 `--fault-via local`（演练脚本在工作台上调用 AWS CLI）；after 之前委派必须已经生效。

### 故障转移（dns/failover-drill，选做）

主记录关联健康检查，停掉 Nginx 后，客户端在“检查间隔 × 失败阈值 + TTL + 缓存”之后拿到备用记录（S3 静态维护页）。

## 平台模式说明

本卡用 `scripts/module enable dns` 一键创建托管区域（或使用你的已有托管区域）与记录。平台通过本会话的 dns 栈确认归属；
你在注册商添加的 NS 委派、在控制台手工建的记录不在平台的回收范围内，结束前请自己处理。
