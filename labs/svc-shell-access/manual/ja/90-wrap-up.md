## このラボでできたこと

- セキュリティグループに管理ポートの受信が 1 つもない状態で、インスタンスへのログインとポートフォワーディングができました。
- SSH の秘密鍵を配布・ローテーションする必要がなくなりました。ログインには IAM ID を使い、認可はインスタンスのタグやセッションドキュメントの単位まで細かくできます。
- 「誰がいつどのコマンドを実行したか」に答えられました。セッション履歴、セッションログ、CloudTrail を照合しました。

## 試験ポイントの振り返り

- Session Manager、踏み台サーバー、EC2 Instance Connect、EC2 Instance Connect Endpoint：どれが 22 番ポートを必要とし、どれがパブリック IP を必要とし、それぞれどう監査するか。
- SSM マネージドノードの 3 つの前提。公開範囲の最小化：受信ルールゼロ、セキュリティグループはステートフル。
- プライベートサブネットから AWS サービスへのアクセス：NAT Gateway とインターフェイスエンドポイント。Session Manager には `ssm`、`ssmmessages`（と、残しておくことが推奨される `ec2messages`）が必要。
- IAM の条件キー（`ssm:resourceTag/*`）で誰がどのインスタンスにログインできるかを制御し、セッションドキュメントでポートフォワーディングの可否を制御する。
- AWS マネージドポリシー `AmazonSSMManagedInstanceCore` とカスタマー管理の最小権限ポリシーのトレードオフ。
