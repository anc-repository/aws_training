## このラボでできたこと

- 同じ MIME を SES から実際に送信し、`/me/outbox` はもう「メールを受け取った」ことの代わりではなくなりました。メールアドレスの確認で所有を証明できるようになりました。
- SES メールボックスシミュレーターで配信、バウンス、苦情を練習し、イベントが SNS → SQS で還流して、バウンスしたアドレスへの必須でないメールの送信が自動で止まることを確認しました。
- 元のメールで DKIM 署名を見て、サンドボックスの制限を体験しました。

## 試験ポイントの振り返り

- SES の ID の検証（メールアドレス / ドメイン）、Easy DKIM、SPF、DMARC、カスタム MAIL FROM。
- サンドボックスと本番アクセス（リージョン単位）。送信クォータと最大送信レート。
- 設定セットとイベント送信先（SNS、CloudWatch、Firehose、EventBridge）。バウンスと苦情、アカウントレベルと設定セットレベルの抑制リスト、評価メトリクスとアカウントの審査。
- SES と SNS のメールサブスクリプションの違い。EC2 は既定でアウトバウンドの 25 番ポートを制限していること。SMTP インターフェイス（IAM から派生させた認証情報）と API インターフェイス。
- Cognito の既定のメールと SES 経由の送信（`scripts/module enable email --param ForCognito=true` が injects で ID を auth に渡します）。
