## 背景

開始状態の CloudAlbum では、すべてのメール（登録確認、パスワードの再設定、コメント通知、日次レポート）が EC2 上の outbox（`.eml` ファイル + `outbox_emails` テーブル）に書かれるだけです。
本人は `/me/outbox` でプレビューし、ページには「本地实现，未真正发信」（ローカル実装、実際には未送信）と表示されます。これで 1 人で登録の流れを最後まで試せますが、ユーザーの実際のメールボックスには何も届きません。
しかも outbox 階層の「メールアドレス確認済み」はメールアドレスの所有を証明できません（誰でも他人のアドレスで登録し、`/me/outbox` で確認リンクを見られます）。

このカードでは同じ MIME を Amazon SES から実際に送信します。配信、バウンス、苦情のイベントは、設定セットのイベント送信先からモジュール付属の SNS トピックに送られ、SQS のフィードバックキューに入ります。
worker がそれを取得して `/admin/outbox` の配信状態と `users.email_status` を更新します。EC2 にインバウンドのポートを開ける必要は一切ありません。

:::why
なぜ EC2 上に postfix を立てて直接配信しないのでしょうか？ EC2 は既定でアウトバウンドの 25 番ポートを制限しています（解除の申請は可能です）。しかも Elastic IP から直接送ったメールは評価が低く、かなりの確率で迷惑メールになります。
SES は評価の高い送信 IP、DKIM 署名、バウンスと苦情の処理、そして送信クォータと送信レートによる保護を提供します。
:::

## 比較実験の予告

### 送信マトリクス（email/send-matrix、必須）

- **SES なし（outbox）**：SES メールボックスシミュレーターの 3 つのアドレスと自分のアドレスに「パスワードの再設定」を 1 通ずつ送らせます。すべてローカルの outbox に書かれ、実際には送信されません。
- **SES あり**：同じ 4 通を SES から送信します。success → 配信済み、bounce → バウンス、complaint → 苦情として、数秒から数分で `/admin/outbox` に還流します。
- **どこで確認できるか**：レポートにある各アドレスの `deliveryStatus`、レスポンスヘッダー `X-CloudAlbum-Path` が `email=outbox:stored` から `email=ses:sent` に変わること、
  そして自分のメールボックスに `DKIM-Signature` 付きのメールが届くことです。
- **期待どおりにならないとき**：まず送信元 ID が検証済みか確認してください。サンドボックス中は、自分のアドレスがその検証済みの ID そのものである必要があります。

### サンドボックスの制限（email/sandbox、必須）

検証していないアドレスに送ります。サーバー側では `failed`、エラー `MessageRejected` として記録され（`/admin/outbox` で赤く表示）、経路セグメントは `email=ses:rejected` になります。
登録自体は通常どおり完了し、アプリが失敗したメールをこっそり「送信済み」に書き換えることはありません。

## 始める前に

- SES の送信元 ID：受信できるメールアドレスを 1 つ（開始前に入力します）。デプロイ後、メールボックスで「Amazon Web Services – Email Address Verification Request」のリンクをクリックします。
- DMARC ポリシーが `reject` ではないメールアドレスをおすすめします。メールアドレス ID で送信すると SPF も DKIM も送信元ドメインとそろわないため、送信元ドメインが `p=reject` を公開していると、
  自分宛てのメールが受信側で拒否されることがあります（公式ドキュメントと実測で確認してください）。
- 任意：自分のドメイン（最後の任意ステップ。ドメイン ID + Easy DKIM には CNAME を 3 件書く必要があります）。
- このカードは最初から最後まで SES サンドボックスの中で行います。サンドボックス中は、検証済みのアドレスと SES メールボックスシミュレーターにしか送信できません。

## プラットフォームモードについて

送信元 ID は終了時に保持を選べます。次に email をデプロイするとき、`scripts/module` は ID がすでにあれば読み取り専用で利用し（`AdoptExistingIdentity=true`）、
同名の ID がすでにあることで失敗することはありません。無効化しても削除されません。
