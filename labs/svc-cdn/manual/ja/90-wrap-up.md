## このラボでできたこと

- EC2 から直接配信していたアルバムを CloudFront の背後に置きました。静的リソースとサムネイルはエッジでキャッシュされ、ヒットすればオリジンに戻りません。
- 偽造できるレスポンスヘッダーを信じるのではなく、サーバー側の証拠（オリジンのログに現れた nonce の回数）で「エッジでのヒット」を証明しました。
- 認証が必要な API が `CachingDisabled` のビヘイビアにあり、2 回ともオリジンに戻ることを確認しました。
- 無効化とバージョン付きファイル名を比較しました。

## 試験ポイントの振り返り

- キャッシュポリシーはキャッシュキーと TTL を、オリジンリクエストポリシーはオリジンに何を渡すかを、レスポンスヘッダーポリシーはブラウザーに返すヘッダーを決めます。
- カスタムオリジンはドメイン名のみです。マネージドプレフィックスリスト + カスタムヘッダーでオリジンを保護し、S3 オリジンには OAC を使います。
- CloudFront で使う ACM 証明書は us-east-1 になければなりません。AWS のオリジンから CloudFront へのトラフィックにはデータ転送料金がかかりません。
- CloudFront はコンテンツをキャッシュします。Global Accelerator はキャッシュせず、静的なエニーキャスト IP を提供します。
