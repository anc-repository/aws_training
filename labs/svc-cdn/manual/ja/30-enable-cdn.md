---
step: enable-cdn
---

CloudFront のカスタムオリジンは**ドメイン名**しか受け付けません。そこでディストリビューションのオリジンを、ラボ用インスタンスの **8080 オリジンリスナー**にします。
このポートは CloudFront 専用です。セキュリティグループは CloudFront のマネージドプレフィックスリストだけを許可し、さらに Nginx があなただけが知っているリクエストヘッダーを検証します。

:::why
プレフィックスリストを許可するだけでは足りません。他人の CloudFront ディストリビューションも同じアドレス範囲から来るからです。リクエストが「あなたの」ディストリビューションから来たことを証明できるのは `X-Origin-Verify` だけです。
:::

:::method{kind=script default}
ワンクリックスクリプトが、オリジン用のシークレットの生成、8080 リスナーの配置、ディストリビューションとオリジン用セキュリティグループのデプロイ、デプロイ完了の待機を行い、最後にメディアの URL を CloudFront に書き換えます。まず変更内容をプレビューします。

```bash {runsOn=workstation}
scripts/module enable cdn --dry-run
```

内容を確認したら実行します（ディストリビューションのデプロイ完了まで待つため、通常は数分かかります）。

```bash {runsOn=workstation}
scripts/module enable cdn
```
:::

:::wait{typical=5 max=20}
**なぜオリジンへのリクエストは 80 ではなく 8080 なのでしょうか？** 80/443 はブラウザーからの直接アクセス用です。8080 は CloudFront 専用で、セキュリティグループは CloudFront のマネージドプレフィックスリストにだけ開いています。
ディストリビューションのデプロイ中も、右側の「アプリのプレビュー」でアルバムを見続けられます。この時点ではまだすべて EC2 から直接配信されています。
:::

デプロイが終わったら、コンソールでこのディストリビューションのオリジンとビヘイビアを見てみましょう。

::console-link[このセッションの CloudFront ディストリビューションを開く]{link=cloudfront.distribution distributionId="{{ var.distributionId }}"}

:::expected
cdn の状態が「正常」、ディストリビューションの状態が「有効」です。オリジンは `{{ target.publicDns }}:8080`、プロトコルは HTTP のみで、`X-Origin-Verify` ヘッダーが付いています。
検証ヘッダーなしで 8080 に直接アクセスすると 403 が返ります。
:::

:::warning
モジュールが管理するディストリビューション（オリジン、ビヘイビア、ポリシー）をコンソールで変更しないでください。プラットフォームはそれをこのカードの完了の証拠として扱います。また、次回の `scripts/module` による更新で変更は上書きされます。
:::

::checks
